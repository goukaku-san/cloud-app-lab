## 7. 前任が踏んだ落とし穴（再発防止）

- `pkill -f` / `pgrep -f` に自分のコマンド行が一致して自分を殺す。バックグラウンド起動は `& echo $! > pidfile` で PID を保存して kill する。
- `out/` は 1 つしかない。サブパスビルドとルートビルド、E2E の並行実行は衝突する。直列にする。
- Tailwind v4 で `className` に `text-sm` を足しても基底の `text-base` に負ける。サイズは props（`size="sm"`）で切り替える実装にしてある。
- ESLint の React ルール: 描画中の `Date.now()`、effect 内の同期 setState、描画中の ref 更新は全部エラー。`useSyncExternalStore` や `useState` 初期化子で回避。
- 画面遷移と同時に状態を変えると `useRouteGuard` が先に別画面へ飛ばす。`paused` を渡してから dispatch する。
- この環境の自動分類器は「公開面を作る」操作（Pages を自動配信するワークフローの push など）を止めることがある。止められたら、公開に関わらない部分だけ進め、オーナーに判断を求める。
- この環境から github.io へは接続できない（配信結果の目視確認は不可）。
- 文章中の「順位」などの語を E2E で禁止語として検査すると、説明文の正当な記述に誤検知する。検査対象を表やカードに絞る。
- `workflow_dispatch` だけのワークフローは既定ブランチにないと登録されず、API 実行は 404 になる。
- `github-pages` 環境は既定で `main` 以外からの配信をはじく（deploy ジョブが 2 秒で失敗、ログなし）。
- （後任・Windows）`npm run build` と `npm run test:e2e` は動かない。scripts が `NEXT_TELEMETRY_DISABLED=1 next build` の POSIX 形式のため。PowerShell では `$env:NEXT_TELEMETRY_DISABLED='1'` を置いてから `npx next build`、`npx playwright test` と分けて呼ぶ。`npm run check` はそのまま動く。
- （後任）E2E は `docs/screenshots/*.png` を毎回上書きする。意図しない差分は `git checkout -- docs/screenshots` で戻してから commit する。
- （後任）「公開してよいか」という言葉で許可を取ると、「本体を世界中の誰でも遊べる」という意味がオーナーに伝わらない（10/30 昼に許可→夜に「まだ早い」）。許可を取る時は「誰が・何を開けるようになるか」を中学生の言葉で 1 行書く。
- （後任）申し送り書の置き場を探すのに時間を使った。この文書は **このリポジトリにしかない**。倉庫メインPCの作業フォルダ（Desktop\Claude Code）・Notion・G ドライブには無い。
