## 0. 決定事項（2026-10-29、株式会社合格の判断）

- 塾に渡すデータは、本人が任意参加した教室単位の匿名の合計のみ。個人のデータは渡さない。
- 広告ターゲティングは引き続き禁止。
- 設計書 v0.1 の 4 章（禁止するゲーム設計）と 12 章（安全・法務）の禁止事項は維持する。

この決定は、設計書 v0.1 の 8 章・10 章・12 章・14 章を補うもので、v0.1 を書き換えるものではない。

## 1. 売り物の定義

| | 内容 |
| --- | --- |
| 商品名（仮） | 教室の星図 |
| 塾が買うもの | 自塾の教室ごとの「今週、生徒たちが現実で行動して帰還した回数」の匿名の合計と、その星空の表示。教室に掲示できる画面と、保護者会で見せられる画面 |
| 塾が買えないもの | 生徒個人の記録、出席、成績、順位、ニックネーム、ひとこと、自己申告の内訳（やった／休んだ）、時間帯。生徒を特定または推測できる一切 |
| 生徒が得るもの | 自分の帰還が教室の星になる体験（共創）。任意参加、いつでも離脱、不参加でも不利益なし |
| 塾が負う約束（契約条項） | 合計以外を求めない。参加を強制しない。参加・不参加を評価や指導に使わない。催促に使わない |

自己申告の内訳と時間帯を渡さないのは、「休んだ生徒が多い」「深夜に動いている」といった情報が、生徒への圧力に変わるのを防ぐため。

## 2. 安全の線引き

### 2.1 サーバーに保存するもの・しないもの

| 保存する | 保存しない |
| --- | --- |
| 教室コード | ニックネーム、ひとこと、分身の設定 |
| 日付（端末ローカル日付） | 自己申告の種類、経過時間、時間帯 |
| その日の帰還の合計（カウンタ） | 個人ごとの帰還ログ |
| その日の参加端末数（日替わりハッシュで数え、翌日に破棄） | 恒久的な端末 ID、IP アドレスの長期保存 |

設計の選択: 「個人ごとのログを保存して離脱時に削除できるようにする」案と、「カウンタだけを保存し個人データをそもそも持たない」案を比べ、後者を採る。離脱後は以後の送信を止めるが、過去の合計から引くことはしない（引ける情報を持たないため）。この点は同意文面に明記する。

### 2.2 表示の線引き

- 最小表示人数 k: 教室の参加端末が k 未満の日は合計を表示しない。k は仮置きで 5。個人の行動が推測できないようにするための設計パラメータであり、業界の基準ではない。専門家確認後に確定する。
- 教室間の比較、順位、平均との差は出さない。
- 塾側にも通知・催促の機能は付けない。
- 教室コードは塾が発行し、学校名・氏名・地域を含まないランダムな文字列にする。

### 2.3 不正・過剰送信への対策

- 送信は帰還 1 回につき 1 件。アプリ内の 1 日の成長上限（3 点）と同様、集計に数えるのは 1 端末あたり 1 日 3 回まで。判定は日替わりハッシュで行い、翌日に破棄する。
- 不参加の端末からは通信ゼロを維持する（受入テストで検証）。

### 2.4 法務（専門家確認が必要。出典のない断定はしない）

- 個人情報保護法上の整理: 教室単位の合計が統計情報として扱えるか、日替わりハッシュの扱い。
- 未成年の同意: 保護者の同意の要否と方法。
- 塾との契約: データの利用目的の限定、再提供の禁止、生徒への強制禁止。
- 表示: 「自己申告であり学習の証明ではない」ことを塾の画面にも常時表示する。

## 3. 同意の流れ

| 主体 | 流れ |
| --- | --- |
| 生徒 | 設定 →「教室に参加」→ 教室コード入力 →「送られるもの／送られないもの」の一覧を表示 → 同意 → 参加。設定からいつでも「教室から抜ける」。抜けた後は以後送らない |
| 保護者 | 保護者向け説明ページに教室の星図の説明を追加。保護者同意の要否と取り方は専門家確認後に確定（仮置き: 塾が入会時に保護者へ説明し同意を得る契約条項 + アプリ内の説明） |
| 塾 | 契約時に 1 章の約束を条項化。管理画面には合計と星空だけが出る |

## 4. 収益モデル

- 課金単位: 教室（または校舎）ごとの月額または年額。金額はこの文書では置かない。
- 式:
  - 年間売上 = 契約教室数 × 教室あたり年額
  - 必要契約教室数 = 目標年間売上 ÷ 教室あたり年額
  - 目標年間売上 = 塾・教育機関の市場価値 × 0.2%
- 入力待ちのため計算しない: 市場価値の出典、教室あたり年額の仮置き値。両方が揃った時点で必要教室数を出す。
- 併用候補（v0.1 の 10 章）: 掲載型スポンサー、保護者同意つき資料請求。いずれもターゲティングなし。
- やらないこと: 広告のために滞在時間を延ばす。学習履歴や自己申告を広告に使う。成果連動で個人データを渡す。

## 5. 一人歩き（自然増殖）との接続

- 配布導線: 塾が生徒に教室コードを配る。アプリは無料のまま。
- 生徒側の動機: 自分の帰還が教室の星空に増える。個人の順位化はしないため、競争ではなく共創。
- 製品力の 3 施策（自分だけの部屋、本物の星図、物語の拡充）は並行して進める。教室の星図は「本物の星図」の最初の形になる。

## 6. 技術構成（追加分）

- バックエンドが必須になる: API（帰還の受信、教室集計の配信）、データベース（PostgreSQL）、塾向け管理画面の認証。生徒側は認証なし。
- 送信は参加に同意した端末だけが行う。送信内容は 3 項目のみ: 教室コード、日付、「帰還 1 回」。
- 日替わりハッシュ: 端末内の乱数と日付から作り、翌日には同じ端末でも別の値になる。名寄せできない。
- 静的 PWA は維持し、不参加の端末は通信ゼロのまま。
- 時計: サーバー時刻へ差し替え（v0.1 の R1 を解消）。
- 既存の `StorageAdapter` と `Clock` の抽象化は、この段階のために置いてある。

## 7. 段階

| 段階 | 内容 | 承認 |
| --- | --- | --- |
| 6a | 本書の承認、法務の専門家確認、k と同意文面の確定 | 必要 |
| 6b | バックエンドと塾管理画面の最小実装。協力塾 1 校でのクローズド試行（同意あり・実データ） | 必要（実データ収集のため） |
| 6c | 試行結果の安全審査 → 一般提供 | 必要（外部公開のため） |

追加の受入テスト:
1. 不参加の端末からは通信が一切ない。
2. 参加端末の送信内容が 3 項目だけである。
3. 参加端末が k 未満の日は塾の画面に合計が出ない。
4. 「教室から抜ける」の後、送信が止まる。
5. 塾の画面に個人を示す情報が一切出ない。教室間の比較が出ない。
6. 塾の画面に「自己申告であり学習の証明ではない」が常時出る。

## 8. 指標

- 塾側（事業指標、個人データ不要）: 契約教室数、継続率。
- 生徒側（匿名集計、本人 opt-in）: 教室参加率、参加後の 7 日後再訪率。
- 北極星指標（v0.1 の 11 章）は維持。
